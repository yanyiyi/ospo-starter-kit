在現代軟體開發中，運用開放原始碼軟體（OSS）不可或缺。
適切運用能大幅提升開發速度與品質。
但另一方面，授權合規與資訊安全等需要注意的地方也很多。

本小節提供適切且有效率運用開放原始碼的實務指南。
從尋找、評估、導入到持續管理，系統性整理了開發者日常所需的資訊。

## 開放原始碼運用的基本流程

要適切運用開放原始碼，以下的分階段做法相當重要。

1. 探索與選擇

    規劃新採用開放原始碼時，請先確認[公司內部已導入 OSS 清單](../using/oss-inventory.md)。
    這份清單收錄了已從授權相容性、資訊安全、技術品質、社群健全性、長期可維護性等觀點評估過的軟體。
    若已有評估過的軟體，從中選擇可以大幅節省時間並降低風險。不過，若使用方式與過去核准時不同，就需要重新確認授權相容性。

    若清單中沒有合適的軟體，請依[OSS 的尋找方式](../using/finding-oss.md)指南，有效率地找出符合需求的候選。
    其中詳細說明了在 GitHub 上的搜尋方式、可信資訊來源的運用、初步篩選的方法等。

2. 評估與驗證

    找到候選後，請依[OSS 的評估方法](../using/evaluation.md)進行綜合評估。
    不只是技術適用性，也需要從授權相容性、資訊安全狀況、社群健全性、長期可維護性等多個角度評估。

    評估分階段進行，可以在維持效率的同時不漏掉重要觀點。
    透過基本檢查、技術評估、資訊安全與風險評估三個階段，適切收斂候選範圍。

3. 授權確認

    授權確認是最重要、卻經常被忽略的環節。
    請在[什麼是授權條款](../compliance/what-is-a-license.md)加深基本理解，並詳細了解特別需要注意的[有原始碼提供義務的授權條款](../compliance/source-disclosure-licenses.md)與[可選擇商用授權的 OSS](../compliance/oss-with-commercial-license-options.md)。

    授權條款的影響會因使用形態大幅改變，因此重點在於先明確專案需求，再判斷相容性。

    主要的使用形態包括以下幾種：
    - **僅公司內部使用：** 限於公司內部開發與運作的使用
    - **對外散布：** 作為軟體產品銷售、搭載於嵌入式裝置、委外開發中交付給客戶等
    - **SaaS 提供：** 透過網路以服務形式提供

    尤其是對外散布的情況，適用的義務會因散布形態而不同，因此需要依具體提供方式加以確認。

4. 導入與整合

    授權確認完成後，就進入實際的導入作業。
    此時請依資訊安全最佳實務，從可信來源下載、驗證雜湊值、執行弱點掃描等。

    此外，導入的開放原始碼軟體請登錄到公司內部的元件台帳（[公司內部已導入 OSS 清單](../using/oss-inventory.md)）。
    這樣才能有效率地進行授權管理、資訊安全監控與相依性追蹤。

## 授權管理的重要性

開放原始碼授權條款是依著作權訂出軟體使用條件的法律授權許可。並不是因為「開放原始碼」就能無限制使用，每份授權條款都有其特有的條件與義務。

不符合授權條件不只伴隨法律風險，也可能造成專案延遲、設計變更、轉移到替代軟體等對開發的嚴重影響。透過事前確認與適切管理，就能避免這些風險。

## 主要的授權條款分類

開放原始碼授權條款可依條件與義務的範圍分成幾個層級：

**義務較少的授權條款（MIT、BSD 等）**
義務相對較少，需要確認的事項有限。主要義務是保留含著作權標示的授權文件，不需要提供原始碼。

**有原始碼提供義務的授權條款（GPL、AGPL 等）**
因為要求衍生物也適用相同授權條件，所以與使用形態的設計密切相關。有些授權條款即使是透過網路提供服務也會產生原始碼提供義務，因此在 SaaS 中使用時特別需要注意。

**只需提供 OSS 部分原始碼的授權條款（LGPL、MPL 等）**
屬於中間定位，在動態連結或模組界線上義務會被緩和。

細節請參閱[什麼是授權條款](../compliance/what-is-a-license.md)與[有原始碼提供義務的授權條款](../compliance/source-disclosure-licenses.md)。

## 資訊安全的考量事項

開放原始碼軟體的資訊安全管理在現代開發中是極為重要的環節。需要多面向的做法，包括監控弱點、適切的更新管理、確保供應鏈安全等。

### 導入時的資訊安全檢查

導入新的開放原始碼時，請執行以下資訊安全檢查：

- **從可信來源下載**：使用官方儲存庫或經認證的套件管理器
- **驗證雜湊值**：確認下載檔案的完整性
- **掃描已知弱點**：在 CVE（Common Vulnerabilities and Exposures）資料庫中確認
- **分析相依性**：包含遞移相依性的完整資訊安全評估

細節請參閱[OSS 的評估方法](../using/evaluation.md)的資訊安全評估小節。

## 洽詢 OSPO 的時機

在以下情況下，若專案內難以判斷，請在推進作業前洽詢 OSPO：

- 授權條款含有**原始碼提供義務、以相同授權條款散布的義務、附上著作權標示與授權文件的義務等，需要依使用形態加以確認的條件**時
- 可能**需要商用授權**時
- **擔心有資訊安全風險**時（請洽詢資訊安全部門）
- 導入**不在公司內部已導入 OSS 清單中的軟體**

若專案內具備授權或資訊安全的知識，也可以自主推進判斷。（*OSPO 不是代替做判斷的組織，而是支援專案做判斷的組織。*）

### 為了有效率的諮詢

洽詢 OSPO 時，請準備以下資訊：

- 對象軟體的名稱、URL、版本
- 預期的商業形態（僅公司內部使用、對外散布（嵌入式裝置、軟體產品、委外開發等）、SaaS 提供等）
- 是否修改以及修改內容
- 專案的期限與背景狀況
- 已評估過的替代方案（若有）
- 與客戶的契約書或產品的使用許可契約書（評估階段的版本也有幫助）
